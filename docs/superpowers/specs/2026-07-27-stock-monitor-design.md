# ggpptt.store 到货邮件监控设计

## 目标

每 5 分钟检查 ggpptt.store 的 `GPT RT Plus 成品号（欧洲渠道）`。商品 ID 固定为 `68`，当前公开库存接口为：

`https://ggpptt.store/user/api/index/commodity?categoryId=2`

当库存从无货变为有货时，通过用户自己的 Gmail 向同一邮箱发送一次提醒。持续有货不重复发送；商品再次售罄后，下一次补货可以再次提醒。

## 运行方式

监控放在公开 GitHub 仓库中，使用标准 GitHub Actions Ubuntu 运行器。工作流支持：

- `schedule`：每 5 分钟执行一次。
- `workflow_dispatch`：用户可手动运行，用于首次配置和故障检查。

GitHub 定时任务可能因平台负载产生延迟，因此 5 分钟是请求频率，不保证提醒恰好在 5 分钟内到达。

公开仓库连续 60 天没有活动时，GitHub 可能自动停用定时工作流。为避免监控静默停止，脚本每 30 天更新一次不敏感的保活日期，由工作流提交到默认分支。

## 最小组件

### `monitor.py`

只使用 Python 标准库：

1. 请求公开库存接口，并设置超时。
2. 验证 HTTP、JSON、接口状态和商品 ID `68`。
3. 将 `stock > 0` 转换为有货状态。
4. 读取 `state.json` 中上次的有货状态。
5. 仅在 `false -> true` 时通过 `smtp.gmail.com:465` 发送 SSL 邮件。
6. 邮件发送成功后才更新状态。
7. 在 `true -> false` 时重置状态，不发送邮件。

邮件包含商品名称、当前库存、价格、检查时间和网站链接。

### `.github/workflows/monitor.yml`

工作流负责检出代码、运行监控脚本，并在 `state.json` 发生变化时提交该文件。工作流只授予 `contents: write` 权限，并使用 `concurrency` 防止定时任务与手动任务重叠。

自动提交使用 GitHub 内置的 `GITHUB_TOKEN`，不需要个人访问令牌。由该令牌产生的提交不会递归触发新的工作流。

### `state.json`

只保存不敏感的去重状态：

```json
{
  "in_stock": false,
  "last_keepalive": "2026-07-27"
}
```

状态文件可以公开，不包含邮箱、密码或购买信息。`last_keepalive` 只用于确保公开仓库在 60 天停用期限前产生活动。

## Gmail 与秘密信息

仓库使用两个 GitHub Actions Secrets：

- `GMAIL_ADDRESS`：用户自己的 Gmail 地址，同时作为发件人与收件人。
- `GMAIL_APP_PASSWORD`：开启两步验证后生成的 Gmail 应用专用密码。

秘密信息不写入代码、状态文件、示例配置或日志。脚本只检查变量是否存在，不输出变量值。

## 状态转换

| 上次状态 | 当前库存 | 行为 |
| --- | --- | --- |
| 无货 | 0 | 静默，不改状态 |
| 无货 | 大于 0 | 发送一次邮件；成功后记为有货 |
| 有货 | 大于 0 | 静默，不重复邮件 |
| 有货 | 0 | 记为无货，等待下次补货 |

第一次运行使用已提交的无货初始状态。若第一次运行时商品已经有货，则发送一次提醒。

## 异常处理

- 网络超时、非成功响应、无效 JSON、接口报错或找不到商品：任务失败，不修改状态。
- 库存值无效：任务失败，不发送邮件。
- Gmail 配置缺失或邮件发送失败：任务失败，不修改状态，以便下一次运行重试。
- 状态文件损坏：任务失败，不自动覆盖，避免错误去重。
- 状态提交失败：邮件可能已经发送；下一次运行可能再次提醒。工作流使用并发锁降低这种情况发生的概率。
- 保活日期每 30 天更新一次；更新失败不影响当次库存检查，但工作流会失败以便用户在 Actions 页面看到。

## 验证

使用 Python 标准库 `unittest` 覆盖以下行为：

- 缺货时不发邮件。
- 首次到货只发一次邮件。
- 持续有货不重复发送。
- 售罄后再次到货会重新提醒。
- 不到 30 天不更新保活日期，到期后只更新一次。
- 接口异常、商品缺失、库存无效、邮件失败时不错误更新状态。

本地测试不访问真实网站，也不发送真实邮件。完成后再通过 GitHub 的手动运行验证公开接口和 Gmail Secrets。

## 明确不做

- 不模拟浏览器、不识别截图。
- 不登录网站、不自动下单。
- 不保存 Gmail 登录密码；只使用应用专用密码。
- 不增加数据库、网页后台、短信或其他通知渠道。
